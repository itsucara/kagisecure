# ADR-0009: Check the generated Swift in; keep the binary artifacts out

- **Status:** Accepted
- **Date:** 2026-09-09
- **Deciders:** M3 implementation
- **Amends:** [architecture.md](../architecture.md) §6, whose `> Assumption:` said generated
  bindings are **not** checked in

## Context

architecture §6 assumed generated bindings would be regenerated by `cargo xtask bindgen` and
never committed, "to avoid review noise while still catching drift". M3 had to actually build the
thing, and the assumption ran into three facts:

1. **SwiftPM cannot resolve a package whose sources do not exist.** The Swift wrapper is a normal
   target in `apps/macos/KagisecureFFI`. With no `.swift` on disk, opening the project in Xcode —
   before any build phase runs — fails, so the editor experience for a fresh clone is a broken
   package rather than a project that builds on ⌘B.
2. **The bindings are the API.** They are the reviewable statement of what crosses the boundary,
   which [ADR-0008](0008-ffi-secret-crossings.md) says must be reviewable. A PR that widens the
   FFI surface should show that widening in its diff, not merely in a `.rs` file whose Swift
   consequences a reviewer has to imagine.
3. **"Review noise" is the wrong worry here.** The surface is 20–30 functions
   ([ADR-0003](0003-uniffi-vs-csbindgen.md)), so the generated file changes only when the API
   changes, which is exactly when a reviewer wants to see it.

The binary artifacts are a different case entirely: a multi-megabyte `.a` per commit is real
repository weight, and nothing about it is reviewable.

## Decision

**Commit `apps/macos/KagisecureFFI/Sources/KagisecureFFI/*.swift`. Do not commit
`apps/macos/KagisecureFFI/Artifacts/` (the static library, the C header, the modulemap or the
xcframework).**

`cargo xtask bindgen`, run locally (this ran in CI until CI was removed on 2026-09-19),
regenerates and the build fails on a diff. The same check also runs
`cargo xtask bindgen` twice and asserts the second run changes nothing, because a generator that
is not idempotent turns every such run into a false failure.

`cargo xtask bindgen` is therefore a required first step in a clean checkout, and `make macos`
does it for you.

## Implementation notes worth keeping

Two things about the generator were not obvious and cost time; they are recorded so the next
person does not rediscover them.

**The modulemap must declare `module`, not `framework module`.** `uniffi-bindgen-swift`'s
`--xcframework` flag emits `framework module <name> { … }`, which describes a real `.framework`
bundle. What `xcodebuild -create-xcframework -library libX.a -headers dir` produces is a
*library* xcframework, whose headers directory needs a plain `module <name> { … }`. Get this
wrong and there is no error: the generated wrapper's `#if canImport(kagisecure_ffiFFI)` quietly
evaluates false, the FFI declarations are never imported, and the build fails with a few hundred
"cannot find type 'RustBuffer' in scope" errors that say nothing about modulemaps. So the xtask
passes `xcframework: false` for the modulemap even though the result is an xcframework.

**The modulemap's module name must be `<basename>FFI`, not `<basename>`.** The default module
name is the library's basename (`kagisecure_ffi`), but the generated Swift imports
`kagisecure_ffiFFI`, matching the header filename. The xtask sets `module_name` explicitly.

Verified on Xcode 26.2 (17C52), Swift 6.2.3, uniffi 0.32.0, macOS 26.1.

## Consequences

**Positive**

- A fresh clone opens in Xcode with a valid package; only building needs the Rust toolchain.
- FFI changes are visible in review on both sides of the boundary.
- The repository stays free of binary blobs.

**Negative — accepted**

- The generated file is ~3,600 lines and will show up in `git blame` and in diff statistics. It
  carries a "This file was autogenerated" header, so it is at least obvious what it is.
- A contributor who edits `kagisecure-ffi` and forgets `cargo xtask bindgen` fails the build
  (previously in CI; now the same check runs locally). The failure message says exactly what to run.
